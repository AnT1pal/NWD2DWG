**NWD2DWG** — универсальный высокопроизводительный BIM-конвертер геометрии из моделей **Autodesk Navisworks (.NWD, .NWC, .NWF)** в форматы **AutoCAD (.DWG, .DXF)**, **glTF / GLB (Web, VR, Blender)** и **IFC 2x3 (BIM-координация)**.

Программа решает ключевую проблему инженеров и BIM-координаторов: Navisworks по умолчанию не позволяет выгружать реальную 3D-геометрию и атрибутику в открытые CAD/BIM форматы для дальнейшей работы в AutoCAD, NanoCAD, Revit, Blender, игровых движках или веб-вьюверах.

## 🚀 Возможности NWD2DWG

### Инженерия и геопривязка (BIM v3.0)
1. **🌐 Сдвиг к нулю (0,0,0) + .wld геопривязка (`--geoshift`):**
   Автоматический перенос модели с огромных геодезических координат (сотни километров) в локальный ноль `(0,0,0)`. Устраняет «дребезг» графики и исчезновение геометрии при открытии в AutoCAD/3ds Max, сохраняя файл мировой геопривязки `.wld` для точного возврата.

2. **📐 Извлечение координационных осей и уровней (`--grids`):**
   Специализированная выгрузка координационных осей и высотных отметок здания в выделенный слой `_GRIDS` / `_LEVELS` в виде чистых CAD-линий (`LINE` / `TEXT`).

3. **🚰 Трассировка осевых линий труб (`--pipes`):**
   Скелетизация цилиндрических сетей и выгрузка осевых линий трубопроводов и воздуховодов с сохранением диаметров (DN) и длин участков (L).

4. **📋 Смета ВОР в Excel/CSV (`--boq`):**
   Автоматический расчет объемов работ (Bill of Quantities): площади поверхностей сеток, объемы, длины трасс, сгруппированные по категориям и материалам.

5. **🚨 Экспорт коллизий в формат BCF 2.1 (`--bcf`):**
   Прямой экспорт результатов Clash Detective в открытый стандарт BCF Zip (BIM Collaboration Format 2.1) со скриншотами, GUID элементов и комментариями.

6. **🔒 Анонимизация конфиденциальных BIM-свойств (`--anonymize`):**
   Очистка персональных данных, коммерческих наименований и конфиденциальных атрибутов перед передачей модели подрядчикам.

7. **🧹 Автоочистка временных файлов TempCleaner (`--clean-temp` / кнопка в GUI):**
   Гарантированное освобождение дискового пространства от промежуточных файлов в `%TEMP%\NWD2DWG`.

---

### Геометрическое ядро v2.0
10. **🔥 Mesh Decimation (QEM-сжатие полигонов 0–90%):**
    Встроенный алгоритм Quadric Error Metrics (QEM) для управляемого упрощения сеток в 2–10 раз.
11. **🧊 Solid Reconstructor (Распознавание тел):**
    PCA-анализ и подгонка примитивов (трубы, цилиндры, балки) в чистые 3D-тела.
12. **📊 BIM Attribute Transfer (XData):**
    Полный перенос свойств Navisworks в AutoCAD XData и атрибуты IFC/glTF.
13. **🎯 Selection Sets & Search Sets:**
    Экспорт строго определенных поисковых наборов.
14. **🌐 glTF 2.0 / GLB Export:**
    Прямая генерация бинарных `.glb` и текстовых `.gltf` файлов для Web/VR/Blender.
15. **🏛️ IFC 2x3 Export:**
    Генерация стандартных файлов IFC (ISO 10303-21 STEP).
16. **🐕 BIM Watchdog (Автоконвертер папок):**
    Фоновый мониторинг директории (`--watch`) с автоконвертацией по расписанию.
17. **⚡ Multi-threaded Engine & Mesh Batching:**
    Параллельная многопоточная обработка с блочной записью Polyface Mesh.

## 📥 Использование

### Графический интерфейс (GUI)
1. Скачайте релиз `NWD2DWG_v3.0.zip` из раздела **Releases**.
2. Запустите `NWD2DWG.exe`.
3. Перетащите файл или папку `.nwd`/`.nwc` в окно программы.
4. Настройте формат вывода и инженерные флаги v3.0 (Сдвиг к нулю, Оси и уровни, Оси труб, Смета ВОР, BCF 2.1).
5. Нажмите **▶ Конвертировать**.

### Командная строка (CLI)

```powershell
# 1. Конвертация NWD в DXF со сдвигом к нулю (0,0,0) и выгрузкой осей _GRIDS
.\NWD2DWG.exe --convert "C:\Models\Plant.nwd" "C:\Out\Plant.dxf" --geoshift 1 --grids 1

# 2. Выгрузка трубопроводов, сметы ВОР и BCF 2.1
.\NWD2DWG.exe --convert "C:\Models\Plant.nwd" "C:\Out\Plant.dxf" --pipes 1 --boq 1 --bcf 1

# 3. Экспорт в IFC 2x3 с анонимизацией свойств
.\NWD2DWG.exe --convert "C:\Models\Plant.nwd" "C:\Out\Plant.ifc" --format ifc --anonymize 1

# 4. Инженерный пакет: ведомость объёмов, масса и центр тяжести,
#    сортамент металла, оси труб, гильзы, высота проходов, 2D-план
.\NWD2DWG.exe --convert "C:\Models\Plant.nwd" "C:\Out\Plant.dxf" ^
  --solid --geoshift --boq --cog --steel --pipes --iso ^
  --penetrations --clearance --section-plan --purge

# 5. Очистка временных файлов
.\NWD2DWG.exe --clean-temp

# 6. Самотест офлайн-алгоритмов (Navisworks не требуется)
.\NWD2DWG.exe --selftest

# 7. Что изменилось с прошлой выдачи. Ни Navisworks, ни исходных моделей
#    не нужно: сравниваются индексы ревизий, их можно переслать смежнику
.\NWD2DWG.exe --diff-index "выдача_01\04_Протокол\2451-14-ТХ_index.csv" ^
                           "выдача_02\04_Протокол\2451-14-ТХ_index.csv"

# 8. История выдач по объекту
.\NWD2DWG.exe --delivery-log "P:\2451-14\_журнал_выдач.csv"
```

## 📊 Ведомости: CSV или книга Excel

Формат задаётся в профиле выдачи («Параметры модулей…» → «Выдача файлов») либо
ключом `--report-format`. Вариант `both` выдаёт и книгу, и CSV.

Разница не в удобстве, а в надёжности данных. У CSV нет ни типов, ни указания
кодировки внутри файла: русский Excel открывает его правильно только с
подсказкой `sep=` и в Windows-1251, числа с запятой распознаются не всегда,
а обозначения вроде `08Х18Н10Т` он норовит превратить в дату. В книге число
хранится числом, текст текстом, кодировка всегда UTF-8, шапка закреплена.

Книга собирается самой программой, без внешних библиотек и без установленного
Excel. Числами становятся только значения, которые числами являются:
обозначения марок и профилей остаются текстом намеренно — именно их порча
и делает ведомость непригодной.

## 🧱 Как читаются материалы

Марка материала берётся из свойств модели. Работает это только при включённом
переносе свойств (`--xdata` и `--materials`, в окне — «BIM-свойства (XData)» и
«Переносить материалы»); если свойств нет, материал распознаётся по имени
элемента и слою, а плотность берётся из параметров модулей.

Две вещи программа делает с маркой сама, и обе — не косметика:

**Сводит написания одной марки.** На реальной модели «Сталь 20» встретилась
тремя вариантами: обычным, строчным и с латинской `C` вместо кириллической.
Латинские двойники в русских марках набирают по привычке к английской
раскладке, а на вид они неотличимы. При группировке ведомости по материалу
такие варианты давали три позиции вместо одной. Теперь для группировки марка
приводится к одному виду, а **в ведомость попадает первое встреченное
написание** — подменять то, что набрал проектировщик, программа не вправе.

**Отсеивает атрибуты отображения.** В свойстве материала попадаются `ByLayer`,
`ПоСлою`, «Индекс цвета AutoCAD 5» — так CAD записывает, откуда берётся цвет.
Материала в них нет, и раньше они шли в ведомость отдельными позициями наравне
с настоящими марками. Теперь такие значения отбрасываются: честное «не задан»
полезнее выдуманной марки. Заодно из-под них проступают настоящие марки,
которые эти значения перекрывали.

## 🔁 Прослеживаемость выдач

Каждая конвертация оставляет два служебных файла, по которым потом можно
ответить на вопросы «что поменялось» и «что мы отдавали в прошлый раз».

* **Индекс ревизии** — `04_Протокол\<шифр>_index.csv`: список элементов с
  габаритами, числом фрагментов и треугольников. Файл небольшой и не содержит
  геометрии, поэтому его можно хранить в системе документооборота или
  отправлять смежнику вместе с моделью.
* **Отчёт об изменениях** — при следующей выдаче в ту же папку программа сама
  находит предыдущий индекс и кладёт рядом `_diff.csv` и `_diff.dxf`.
  В DXF изменения помечены крестами с подписями по категориям, файл
  накладывается на модель как отдельный слой.
* **Журнал выдач** — `_журнал_выдач.csv`: одна строка на прогон (дата, модель,
  её размер и дата правки, число элементов, сколько файлов выдано, шаблон,
  пользователь). Файл дописывается, а не перезаписывается, поэтому его можно
  положить в сетевую папку и вести всей группой.

Геометрия без собственного имени различается по месту: она попадает в индекс
с привязкой к ячейке сетки в два метра. Иначе на моделях, где имён нет вовсе,
весь объект схлопывался в одну строку индекса и сравнение теряло смысл. Предел
здесь честный: связать безымянную геометрию между ревизиями больше не по чему,
поэтому переезд дальше двух метров читается как «удалено и добавлено».

Категории изменений различаются так: сначала сравниваются габариты, затем
положение. Элемент того же размера в другом месте — «смещён»; изменившийся в
размере — «изменена форма» (при изменении размера центр почти всегда сдвигается,
поэтому обратный порядок вводил бы в заблуждение). Совпавшие габариты и центр
при другом числе треугольников — «геометрия перестроена». Пороги задаются в
настройках: смещение в миллиметрах и изменение числа треугольников в процентах.

Всё это работает и без Navisworks — сравнение читает только индексы:

```powershell
.\NWD2DWG.exe --diff-index старый_index.csv новый_index.csv отчёт.csv
```

## 🤖 Управление извне: MCP-сервер

`mcp\nwd2dwg_mcp.py` — сервер [MCP](https://modelcontextprotocol.io) поверх
командной строки программы. Он позволяет управлять конвертером из любого
клиента MCP, в том числе голосом языковой модели: «прогони модель по шаблону
КМ», «покажи, что изменилось с прошлой недели», «сколько тонн в ведомости».

Зависимостей нет — нужен только Python 3.8+. Подключение:

```json
{
  "mcpServers": {
    "nwd2dwg": {
      "command": "python",
      "args": ["C:/rhinodwg/NWD2DWG/mcp/nwd2dwg_mcp.py"],
      "env": { "NWD2DWG_EXE": "C:/rhinodwg/NWD2DWG/dist/NWD2DWG.exe" }
    }
  }
}
```

Проверка настройки: `python mcp\nwd2dwg_mcp.py --check`

| Инструмент | Что делает |
|---|---|
| `probe` | Разведка модели без конвертации |
| `diagnostics` | Проверка окружения: Navisworks, AutoCAD, плагин, права |
| `list_presets` | Встроенные и пользовательские шаблоны настроек |
| `list_settings` | Текущие параметры расчёта и профиль выдачи |
| `convert` | Конвертация с шаблоном, ключами и параметрами |
| `diff_index` | Сравнение двух выдач |
| `delivery_log` | Журнал выдач по объекту |
| `read_output` | Чтение протокола или ведомости (кодировка определяется сама) |
| `list_outputs` | Состав папки выдачи с размерами и датами |
| `selftest` | Самотест расчётных модулей |

Ключи конвертации сервер принимает только из закрытого списка: произвольную
команду через него выполнить нельзя. Изменяющие инструменты помечены
`destructiveHint`, чтобы клиент спрашивал подтверждение.

## 🧠 ИИ-помощник (вкладка «ИИ-помощник»)

Подключение языковой модели сделано так, чтобы им можно было пользоваться
в закрытом контуре и чтобы отказ от него ничего не ломал.

* **По умолчанию выключено.** Пока галка снята, программа не делает ни одного
  сетевого обращения.
* **Режим «только локальные адреса»** (включён по умолчанию) физически
  запрещает обращения куда-либо, кроме этой машины: подходят Ollama,
  LM Studio, vLLM и любой локальный сервер с OpenAI-совместимым API.
* **Маршрутизатор** перебирает провайдеров сверху вниз, первый ответивший
  выигрывает. Так локальную модель можно держать основной, а внешний шлюз —
  резервным.
* **Ключи** шифруются средствами Windows (DPAPI) под учётной записью
  пользователя и на диск открытым текстом не попадают. Настройки ИИ лежат
  отдельным файлом `%APPDATA%\NWD2DWG\ai.json` и не входят в шаблоны, чтобы
  чужой ключ не уехал вместе с настройками расчёта.
* **Передача имён элементов** — отдельная галка: имена раскрывают состав
  проекта, поэтому по умолчанию наружу уходят только обезличенные сводки.

Расчёты языковая модель не выполняет и выполнять не будет: результат должен
быть воспроизводим и защитим на экспертизе. ИИ работает поверх готовых
данных — объяснить протокол, подсказать шаблон, разобрать формулировку задачи.

## 🗺️ Дорожная карта развития (Планы разработки)

Экосистема **NWD2DWG** последовательно закрывает ключевые разрывы между закрытыми форматами и открытой практикой проектирования на всех этапах жизненного цикла объекта:

### 🔹 Версия 3.1 — Координация и 2D-генерация
- **🚨 Smart Clash Clusterer (DBSCAN):** Пространственная кластеризация пересечений Navisworks Clash Detective — автоматическая группировка тысяч коллизий по физическим трассам труб, лотков и стенам с отсевом 90% шума.
- **📐 Section2Plan (2D Vectorizer):** Автоматическая нарезка плоских поэтажных планов и разрезов из сводной 3D NWD-модели на заданной высоте (отметка +1.200 м) в виде нативных 2D `LWPOLYLINE` стен, колонн и проемов.
- **🧹 Deep CAD Optimizer:** Глубокая очистка результирующих DWG/DXF от неиспользуемых блоков, DGN-типов линий и таблиц слоев для мгновенного открытия чертежей.

### 🔹 Версия 3.2 — Инженерия и валидация данных
- **🏗️ Steel Profile Matcher (ГОСТ Профили):** Анализ сечений металлических балок и колонн из полигональных сеток, определение сортамента по ГОСТ (двутавры ГОСТ 26020, швеллеры ГОСТ 8240, трубы ГОСТ 8732) и расчет ведомости металла (КМ/КМД).
- **📋 Unified Property Normalizer:** Приведение неструктурированных вкладок свойств разнородных моделей (IFC, RVT, DWG, STEP) к единому классификатору ГОСТ / buildingSMART BSDD.
- **🔍 Open IDS Rule Engine:** Автоматическая валидация информационной полноты элементов модели по стандартам EIR/BEP через открытые спецификации Information Delivery Specification (`.ids`).

### 🔹 Версия 3.3 — 4D Планирование и эксплуатация (Asset Management)
- **⏱️ 4D Schedule Auto-Mapper:** Автоматическое сопоставление календарных графиков производства работ (MS Project XML / Primavera XER / CSV) с геометрией по кодам WBS/этажам и экспорт цветной пошаговой анимации монтажа.
- **🛡️ Bounding BRep Shrinkwrapper:** Защита интеллектуальной собственности и ноу-хау оборудования — генерация габаритных выпуклых оболочек (Convex Hull / OBB) с сохранением монтажных фланцев и точек подключения сетей.
- **📊 Open COBie Spreadsheet Builder:** Автоматическая выгрузка структуры Проект → Здание → Этаж → Помещение → Оборудование в стандартный паспорт эксплуатации COBie (Excel).

## ⚠️ Ограничения текущей версии

| Функция | Состояние |
|---|---|
| Координационные оси (`--grids`) | Уровни (`_LEVELS`) выгружаются по `GridLevel.Elevation`. Геометрию самих осей публичный API Navisworks не раскрывает: `GridLine` содержит только имя. |
| 3D BIM Diff, пространственный тайлинг | Реализованы только базовые функции (сравнение наборов, расчёт индекса тайла); отдельного CLI-режима нет. |
| Свойства элементов (`--xdata`) | Пишутся как `TEXT` на слое `<слой>_BIM` рядом с геометрией, а не как настоящий XDATA: группа 1001 требует регистрации APPID в таблице. |
| Помещения (`--room-finish`) | В NWD нет объектов-помещений, поэтому контуры восстанавливаются по замкнутым полилиниям горизонтального среза. Для технологических моделей без архитектуры результат будет скудным — это ограничение исходных данных, а не расчёта. |
| Сортамент стали | База — только ГОСТ (8240, 26020, 8509, 30245, 8732). Европейского и СТО сортамента в базе нет. |
| Гильзы и проёмы | Стены и перекрытия опознаются эвристикой по форме габаритного параллелепипеда. На нетиповых конструкциях требует калибровки порогов в параметрах модулей. |

### Что требует данных в самой модели

Три модуля работают только если соответствующие данные есть в NWD:

| Модуль | Источник | Если данных нет |
|---|---|---|
| `--bcf`, `--clash-cluster` | Сохранённые проверки Clash Detective | В журнал пишется «в модели нет проверок Clash Detective» |
| `--4d` | Задачи TimeLiner, либо файл графика по ключу `--schedule` | Сообщение с указанием, что переключить |
| `--room-finish` | Замкнутые контуры на отметке среза | Сообщение с фактическими порогами площади |
